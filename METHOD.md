| Ветка верификатора | **3. Проверка данных.** Объекты проверки — измерения качества, последовательности, матрицы численности и статистика обработки. |

## 1. Замысел

**Вопрос.** Совпадут ли последовательности ASV, число ридов каждого ASV в каждом образце и числа ридов на этапах DADA2 при трёх выполнениях одной команды на одном входе?
**Гипотеза.** При фиксированных данных, обрезке, версии программ и числе потоков все три содержательных результата совпадут точно.
**Ответ.** Для каждой из трёх пар запусков привести число различающихся последовательностей, ячеек таблицы ASV и значений статистики. Для каждого образца показать вход, число нехимерных ридов, процент сохранённых ридов и число ASV с ненулевой численностью. Итоговый вердикт определяется в §7.

## 2. Постановка

| Что | Значение |
|---|---|
| Меняем | Только номер технического запуска DADA2 (1, 2, 3). Каждый раз выполняется метод для всех 11 образцов вместе. |
| Фиксируем | Один импорт R1, порядок ридов, состав образцов, окружение, одна пара обрезки `L = trim-left`, `T = trunc-len`, 6 потоков. Решение о `L,T` предшествует всем трём запускам. |
| Параметры DADA2 | `denoise-single`, `max_ee=3`, `min_fold_parent_over_abundance=2`. Параметры версии 2025.7.0 фиксируем как `trunc_q=2`, `pooling_method=independent`, `chimera_method=consensus`, `allow_one_off=False`, `n_reads_learn=1000000`, `hashed_feature_ids=True`, `retain_all_samples=True`. |
| Измеряем | До обрезки — качество в единицах Phred Q по позициям в нуклеотидах. После обработки — целые числа ридов и ASV, долю сохранённых ридов в процентах и расхождения между повторами. |
| Базовая линия | Для входа — принятая таблица числа ридов и счётчики QIIME 2. Для повторяемости — нулевое расхождение при сопоставлении одинаковых объектов. Для испытаний кода — маленький пример с вычисленными вручную ответами. |

**Решение об обрезке.** Показать человеку полный профиль каждого образца, включая `K_S63`. У всех графиков общие оси, по горизонтали позиция от 1, по вертикали Phred Q, линия медианы и полоса между квартилями. Рядом показать общее качество по образцу. Человек отмечает, где начинается устойчивое снижение, либо что однозначной границы не видно. В `memory/denoise_choice.md` он фиксирует `L,T`, наблюдения по образцам, использованный критерий и дату. Для данной схемы `0 ≤ L < T ≤ 251`. Сохранить этот выбор отдельным коммитом до запуска №1. Исторические `10/150` — справочные значения. Факт удаления праймеров неизвестен.

[источник] Проектные правила и способ записи решения — [AGENTS.md](AGENTS.md) и [denoise_choice.md](memory/denoise_choice.md). Параметры метода сверены с [реализацией q2-dada2 2025.7.0](https://github.com/qiime2/q2-dada2/blob/2025.7.0/q2_dada2/_denoise.py).

## 5. Верификатор

Исполнитель готовит `checks/verify_denoising.py` с договором из §3. Защиту `checks/` восстанавливают после установки проверенного файла. `checks/check.py` остаётся общей проверкой всего проекта. У верификатора есть три режима:

| Вызов | Что считается успехом |
|---|---|
| `--self-test` | На версионированных миниатюрных данных правильные варианты приняты, каждое намеренное повреждение возвращает свой ожидаемый код. |
| `--quality-only` | Все 11 профилей и общие показатели сверены с исходными R1. Вердикт явно помечен как проверка качества исходных данных. |
| Без аргументов | Выполнены самопроверка, проверка профилей, договора трёх запусков и решение по §7. Только этот режим выдаёт полный `PASS`. |

Для демонстрации доверия зафиксировать ожидаемые исходы **до испытаний**:

| Изменение в тестовой копии | Ожидаемый результат |
|---|---|
| Корректный пример и его версия с переставленными строками, столбцами и записями FASTA | Обе дают `PASS` в соответствующем режиме. |
| В одной позиции известны Q=10 и Q=30 | Ожидаются Q25=15, медиана=20, Q75=25. Подмена медианы на 21 даёт `QUALITY_VALUE`. |
| Повтор строки образца, в том числе при сохранении прежнего множества идентификаторов | `SAMPLE_KEY` |
| Подмена `trim_left` только в provenance при корректном зафиксированном решении | `PROVENANCE` |
| Удлинение одной репрезентативной последовательности на основание | `ASV_LENGTH` |
| Добавление одного рида в ячейку без изменения статистики | `READ_BALANCE` |
| Перенос одного рида между двумя существующими ASV одного образца только в повторе №3, с неизменной суммой по образцу | `REPEAT_DIFFERENCE` |
| Копирование всего корректного запуска №1 на место №3 | `REUSED_RUN` |

Испытания изменяют рабочие копии синтетических данных и проверяют смысл ошибки. Для сквозного теста читателя QZA нужны три комплекта с известными ответами. Исполнитель фиксирует их формат и хеши вместе с кодом. Технический сбой или обнаружение изменённой контрольной суммы сами по себе не засчитываются как обнаружение указанного смыслового дефекта.

## 7. Правило принятия, записанное до первого прогона

1. **Метрики и единицы.** Для каждой пары запусков считать размер симметрической разности множеств ASV (последовательностей), число несовпадающих ячеек матрицы (ячеек) и наибольший модуль их разности (ридов), число различий в четырёх целых счётчиках по образцам (значений). Доля сохранённых ридов равна `100 × non-chimeric / input` по каждому образцу, в процентах. Счётчики для вердикта брать до округления процентов.
2. **Повторы.** Ровно три технических запуска одного протокола на полном входе. Рераны проверки на одних выходах в число запусков DADA2 не входят. Попытку, прерванную технической ошибкой, сохранить в журнале вместе с причиной.
3. **Способ сравнения и уровень значимости.** Попарное точное сопоставление запусков 1–2, 1–3, 2–3 по стабильным ключам. Сначала проверить состав ключей, затем сопоставить биологические последовательности, матрицу численности и статистику. Порядок строк, идентификаторы архивов и даты исключить из числового сравнения. **Уровень значимости α неприменим**. Здесь проверяется равенство всех элементов конечного набора. Три повтора на одних ридах не дают трёх независимых биологических наблюдений. P-значения, доверительные интервалы и поправка за множественные сравнения в правило не входят.
4. **Практический порог и его источник.** Допустимое расхождение во всех четырёх метриках сравнения — **0** во всех трёх парах. Источник порога — проверяемое требование точной воспроизводимости целочисленного результата: одна иная последовательность или один иначе отнесённый рид уже меняют данные, подаваемые на классификацию. Для текстового экспорта Q и процентов допускается только погрешность округления до шести знаков (абсолютно ≤0,0000005 в единицах соответствующего столбца).
5. **Выбор и вердикт.** Все 11 образцов, три повтора и три пары обязательны. `PASS/0` — полный комплект, самотест пройден, список нарушений пуст, все расхождения нулевые и нет условия остановки. `FAIL/1` — нарушение договора, несовпадение либо провал обязательного самотеста. `INCOMPLETE/2` — отсутствует обязательный вход, решение человека или запуск, возникла техническая ошибка либо требуется решение по сохранности. При уже выявленном нарушении сохранить `FAIL/1` и перечислить также недостающие данные. Лучший повтор не выбирается.
6. **Разбиение для вывода.** Вывод о повторяемости распространяется на все 11 заранее перечисленных образцов при одном фиксированном протоколе. `K_S63` проходит те же проверки, его риды и ненулевые ASV вывести отдельно. Для десяти почвенных образцов показать отдельные доли сохранности, включая `LUB3_S93`. Синтетические примеры служат только испытанию верификатора.
7. **Остановка.** Если у почвенного образца `non-chimeric=0` — `FAIL/1`. Если сохранность положительна, но ниже 30%, остановить дальнейшие запуски и сообщить человеку согласно §2 AGENTS.md. Порог относится к разбору качества обработки. Изменение `L,T` после просмотра результатов требует новой версии методики и нового полного набора из трёх повторов. Вердикт характеризует повторяемость и согласованность обработки. Биологическую истинность ASV и оптимальность обрезки он не устанавливает.
