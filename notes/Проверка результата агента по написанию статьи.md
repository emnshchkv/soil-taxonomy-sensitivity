## Причина остановки и расход токенов

Основной запуск: 17 ноября, примерно 13:40–13:51 по Москве. Журнал завершения содержит ERROR о достижении локального лимита. Служебное поле CLI `exit_type: normal` не доказывает успех задачи: перед ним явно записана ошибка `Rate limit exceeded`.

Локальный счётчик `~/.ai4science_budget.json` на момент аудита: дата `2026-11-17`, **2 719 010 токенов**. Лог подтверждает порог **2 700 000** и прекращение новых запросов с ошибкой `daily_token_limit`. Превышение порога — 19 010 токенов; до пользовательских 3 000 000 по этому локальному счётчику остаётся 280 990. Это общий учёт за день, а не доказанный расход только одного запуска; обращения в обход этого счётчика здесь не учитываются.

Последний успешный запрос: **76 241 входной + 83 выходных = 76 324 токена**, из входа 75 520 отмечены как cache_read_input_tokens. Настройка запуска на 64 000 контекста не удержала фактический вход API ниже этого значения. Причина расхождения оценок/сжатия в этом аудите не установлена. Суточный proxy считает usage.total_tokens, включая повторно переданный кэшированный вход; маленький ответ не означает маленького расхода суточного счётчика. Служебное поле total_tokens=76324 в завершении CLI совпадает с последним запросом и не используется здесь как сумма за сессию.

Последний сохранённый запрос содержит 106 сообщений и 52 вызова инструментов в истории: 33 shell, один pdf_info, один write, четыре pdf_read, три pdf_search, три load_artifact, семь openalex_search. Последние успешные ответы имели входы порядка 69–76 тысяч токенов. Эти наблюдения подтверждают значительные затраты на многократную передачу накопленной истории; точная причина отсутствия ожидаемой экономии требует отдельной проверки запуска/сжатия.
