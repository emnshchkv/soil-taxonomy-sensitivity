## Цель проекта
Методологический вопрос: насколько состав бактериальных сообществ почв Москвы (16S рРНК, QIIME 2 2025.7) и выводы о нём зависят от выбора алгоритма таксономической классификации и референсной базы при фиксированной обработке ридов. Обработка ридов (денойзинг DADA2) выполняется один раз, поэтому все методы получают одни и те же ASV; пороги классификаторов — по умолчанию.
Дизайн из двух факторов: (1) алгоритмы на одной базе SILVA 138 (99%): `classify-sklearn`, `classify-consensus-vsearch`, `classify-consensus-blast`; (2) базы при одном алгоритме (`classify-sklearn`): SILVA 138, GTDB (последний релиз), Greengenes2.
Результатом считается короткий отчёт с количественным сравнением методов: согласованность присвоений между методами по рангам и доля неклассифицированных ASV (меньше — лучше как показатель полноты аннотации; это не мера точности). Согласованность измеряется после приведения номенклатур к общему виду по таблице соответствий (SILVA ↔ GTDB ↔ Greengenes2).

## Данные и материалы
- `data/` — исходные данные:
  - `data/raw/` — демультиплексированные риды 16S в формате `.fastq.gz` (Phred33). Анализируются только single-end риды; если для образца есть пара R1/R2, используется только R1 (forward). Только чтение.
  - `data/meta/` — таблицы метаданных образцов (район, тип землепользования и др. экологические параметры), манифесты QIIME 2 (`.tsv`), таблица соответствий таксономических номенклатур (SILVA ↔ GTDB ↔ Greengenes2, уровень типа и класса — минимум). Единицы измерения указывать в заголовках столбцов.
  - `data/refs/` — референсные базы и обученные классификаторы: SILVA 138 (99%), GTDB, Greengenes2; версии и контрольные суммы фиксировать в `data/refs/VERSIONS.md`.
  - Выборка для методологической задачи: 11 образцов — отрицательный контроль (K_S63, амплифицированная вода), почвы Крылатского (Kr1–Kr5) и Люблино (LUB2–LUB6), все как single-end; контроль идёт через тот же денойзинг, но исключается из сравнений состава почв и используется для поиска контаминантов (манифест `SingleEndFastqManifestPhred33V2`, `qiime dada2 denoise-single`); выборка намеренно небольшая, чтобы не усложнять.
  - Амплифицируемый регион 16S: V4–V5. Классификаторы для всех баз готовить под этот регион одинаково (`feature-classifier extract-reads` с теми же праймерами), чтобы сравнивать базы, а не способ обучения.
  - Положительный контроль есть (тип и состав: <уточнить>); среди 11 файлов в `data/raw/` его нет (K_S63 — отрицательный контроль). Нужен в `data/raw/` как эталон для оценки точности, а не только согласованности.
  - Список экологических параметров: <уточнить>.
- `paper/` — статьи и заметки по классификации ампликонных данных (q2-feature-classifier, RESCRIPt, особенности SILVA/GTDB/Greengenes2), методам сравнения таксономических профилей; черновик отчёта.
- Фиксированная стратегия денойзинга и её обоснование записываются в `memory/` до начала сравнения.
- Исходные данные не изменять; производные файлы (`.qza`, `.qzv`, таблицы, рисунки) — в отдельных папках.

## Как работать
- Код — в `src/`, запускать перед тем, как сообщать результат.
- Каждый вывод сопровождается способом его проверки.
- Сводки и заметки для следующих сессий — в `memory/`.
