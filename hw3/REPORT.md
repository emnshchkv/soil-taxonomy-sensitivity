## 1. Потребность и инструмент

`[порождено]` Чтобы подготовить справку к рисунку статьи, агенту надо найти в итоговой TSV-таблице три строки одной пробы и правильно определить знаменатель доли. Инструмент `family_profile` делает это по идентификатору пробы. Для каждой модели он возвращает число ридов после DADA2, число ридов, вошедших в семейственный профиль, и число и долю ридов без назначенного семейства. Если в профиль не вошёл ни один рид, доля возвращается как NA.

| Поле | Значение |
|---|---|
| Файл инструмента | `hw3/tool/family_profile_mcp.py` |
| Файл запуска MCP-сервера | `hw3/tool/family-profile-mcp` |
| Сигнатура | `family_profile(sample_id: str) -> dict` |
| Аргумент | `sample_id` — идентификатор пробы из столбца `sample`, например `Kr2_S81` |
| Источник данных | `results/paper_step4/20261118/family_sample_counts.tsv` |

**Строка документации из исходного кода:**

```python
    """
    Данные к рисунку статьи: счётчики ридов по семействам для одной пробы почвы или контроля.

    Вызывать, когда нужно назвать числа к рисунку или таблице статьи по семействам:
    сколько ридов осталось после DADA2, сколько отобрано для профиля семейств, сколько
    ридов осталось без назначенного семейства и какой это процент от отобранных, —
    сразу для трёх моделей таксономии (sklearn_silva138, sklearn_gtdb, sklearn_gg2).

    sample_id — идентификатор пробы ровно как в столбце sample таблицы, например
    "Kr2_S81", "LUB2_S92", "K_S63" (отрицательный контроль). Совпадение точное,
    регистр важен; список допустимых значений — в поле known_samples ответа на ошибку.

    Возвращает словарь: sample_id, source (относительный путь к исходному TSV) и records —
    три записи по одной на модель с полями model, post_dada2_reads, selected_reads,
    unclassified_family_reads (целые числа) и unclassified_pct_of_selected (строка из TSV
    с сохранённой точностью; "NA", если отобранных ридов ноль и процент неопределим).
    При неизвестной пробе, отсутствии таблицы, дубликате или пропуске строки модели
    возвращает словарь с полем error. Только чтение, файлы проекта не меняются.
    """
```

## 2. Вызов по описанию `[написано]`

Подробный отчет вызова лежит в `./evidence/mcp-tool-call.md`.

Запрос пользователя:

```
> Для пробы Kr2_S81 покажи, сколько ридов вошло в семейственный профиль у каждой из трёх моделей и у какой модели доля ридов без назначенного семейства неопределима. Объясни почему.
```

Строка вызова из сеанса:

```
▸ family_profile family-profile-mcp
    sample_id: Kr2_S81
```

Trimmed ответ:

```
| Модель           | Вошло в профиль (N) | Без семейства |    Доля без семейства |
|------------------|---------------------|---------------|-----------------------|
| sklearn_silva138 |               **0** |             0 | **NA (неопределима)** |
| sklearn_gtdb     |            **8013** |          8013 |                 100 % |
| sklearn_gg2      |            **8098** |          8098 |                 100 % |

**Неопределима у SILVA.** Доля считается как `unclassified_family_reads / selected_reads`, а у SILVA `selected_reads = 0`: знаменатель нулевой, деление не определено, поэтому в таблице стоит `NA` (по контракту `research/paper_results_contract.md`: «При N=0 доля NA»). Это не пропуск данных и не ошибка агрегации.

**Почему у SILVA ноль отобранных:**  Bacteria + Archaea после отбора = 0. Отбор идёт отдельно по каждой модели, поэтому GTDB и Greengenes2 на тех же ридах сохраняют 8013 и 8098: у них эти ASV назначены как Bacteria (например, ASV `121fc77a…` — 1002 рида, который SILVA относит к Eukaryota/Didymellaceae, а GTDB и GG2 только к Bacteria). У GTDB/GG2 все отобранные риды имеют лишь `d__Bacteria` без семейства — отсюда 100 %, но знаменатель ненулевой, и доля определена.
```

## 3. Сценарий `[порождено]`

Задача из `scenario/task.md` — подготовить справку к рисунку статьи по почвенной пробе Kr2_S81. Генератор составил таблицу для SILVA 138, GTDB и Greengenes2 и пояснил, почему доля ридов без назначенного семейства в одном случае равна NA, а в двух других — 100%. 

Критик самостоятельно вызвал MCP-инструмент `family_profile` для той же пробы. Для каждой модели он сверил четыре значения: число ридов после DADA2, число ридов в профиле, число ридов без назначенного семейства и их долю среди вошедших в профиль. Дополнительно он сверил числа с `results/paper_step4/20261118/family_sample_counts.tsv`, а определение знаменателя — с `research/paper_results_contract.md`. Рецензию он записал в `bus/review_1.md`.

Таблица раундов:

| Раунд | Генератор записал | Вердикт критика | Чем проверено |
|---|---|---|---|
| 1 | `bus/draft_1.md` | принято |	MCP-вызов `family_profile(sample_id="Kr2_S81")` и сверка со строками 4, 15 и 26 исходной TSV-таблицы |

**Итог:** черновик принят в первом раунде. Критик подтвердил, что у SILVA в профиль вошло 0 ридов, поэтому доля неопределима (NA). У GTDB и Greengenes2 в профиль вошли 8 013 и 8 098 ридов соответственно. Все они остались без назначения до семейства, поэтому обе доли равны 100%. Доработка не потребовалась.

## 6. Что не получилось `[написано]`

Агент попытался дополнительно сверить исходную таблицу командой grep -P. Установленная в macOS версия grep отклонила этот параметр. Агент повторил выборку через awk, указав разделитель табуляции и отбор по столбцу sample, и получил три строки для Kr2_S81. **Сам MCP-инструмент был вызван до этой дополнительной сверки.**

При подготовке сценария выявили две ошибки стартового скрипта: он продолжал выполнение после сбоя роли и мог принять строку `ВЕРДИКТ: принято с оговоркой`. Обработку исправили и проверили на изолированных запусках с имитацией сбоя и некорректного вердикта. В фактическом прогоне обе роли завершились с кодом 0.
