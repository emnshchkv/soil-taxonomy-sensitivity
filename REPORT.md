## 1. Задача и место верификатора

Исследуется вопрос: совпадут ли последовательности ASV, число ридов каждого ASV в каждом образце и числа ридов на этапах DADA2 при трёх выполнениях одной команды на одних входных данных.

Верификатор проверяет повторяемость денойзинга — центрального этапа пайплайна анализа ампликонов 16S рРНК. Ошибка на этом этапе (разные ASV при повторном запуске) делает невозможным воспроизведение таксономической классификации и всех последующих выводов о составе микробиома.

Верификатор не проверяет биологическую корректность ASV, оптимальность параметров обрезки или качество таксономической классификации.

## 2. Методика

**Замысел.** При фиксированных данных, обрезке, версии программ и числе потоков все три содержательных результата совпадут точно.

**Постановка.** Меняется только номер технического запуска DADA2 (1, 2, 3). Фиксируются: один импорт R1, порядок ридов, состав 11 образцов (10 почвенных + K_S63), окружение qiime2-amplicon-2025.7, параметры обрезки L=20, T=200, 6 потоков.

**Данные.** 11 пар FASTQ R1/R1 московских почв, длина 251 нуклеотид. Версия: коммит `4ea5d0e043fd3f06d79940db047618e9bb0ee941`.

**Правило принятия.** Все четыре метрики (размер разницы ASV, число несовпадающих ячеек, максимальная разница ридов, число различий счётчиков) должны быть нулевыми во всех трёх парах.

Методика записана до первого прогона в коммите `a398c5f`.

## 3. Верификатор

- **Что проверяет:** повторяемость трёх запусков DADA2 denoise-single на одних входных данных.
- **Как устроен:**
  - `validate(data)` — проверка договора: provenance, баланс ридов, статистика, уникальность ключей.
  - `run_metrics(data)` — попарное сравнение трёх запусков: четыре метрики.
  - `check_quality(root, out)` — проверка входных хешей и профилей качества.
  - `read_repeats(root, out, counts, choice, paths=RUNS)` — загрузка трёх QZA и вызов validate + run_metrics.
  - Три режима: `--self-test` (синтетика), `--quality-only` (профили), полный (без аргументов).
- **Чего не проверяет:** биологическую корректность ASV, оптимальность trim-left/trunc-len, качество классификации, наличие контаминантов в K_S63.

Таблица свойств:

| № | Свойство | Почему должно выполняться | Тест |
|---|---|---|---|
| 1 | Уникальность ключей (sample-id, position) | Договор: каждая запись уникальна | duplicate_code="SAMPLE_KEY" |
| 2 | Баланс ридов: sum(frequencies) = non-chimeric | Биологически: каждый рид отнесён к одному ASV или отброшен | READ_BALANCE |
| 3 | Прогрессия счётчиков: input ≥ filtered ≥ denoised ≥ non-chimeric | Фильтрация не добавляет риды | STATS_COUNT |
| 4 | Уникальность execution UUID | Каждый запуск имеет уникальный UUID | REUSED_RUN |
| 5 | Нулевые метрики совпадения | Три запуска на одних данных дают одинаковый результат | REPEAT_DIFFERENCE |
| 6 | Квантили в [0,93] | Phred Q в диапазоне 0–93 | QUALITY_VALUE |
| 7 | Длина ASV = T−L | Обрезка фиксирована | ASV_LENGTH |

## 4. Декомпозиция проверки

```

├── Проверка входных данных (хеши, профили) — закрыта: check_quality()
```

## 8. Ограничения

1. **Сохранность Kr5_S84.** 2.51% — значительно ниже порога 30%. Три повтора совпали точно (метрики 0,0,0,0), но биологическая интерпретация требует проверки.
2. **Отсутствие праймеров.** Точные последовательности неизвестны; trim-left=20 — эмпирический выбор.
3. **Однопоточность R.** DADA2 использует R-бэкенд; при изменении числа потоков результаты могут отличаться.
4. **Только R1.** R2 не используется для денойзинга.
5. **Верификатор.** Проверяет только повторяемость трёх запусков. Не проверяет биологическую корректность ASV, оптимальность обрезки, или качество классификации.
6. **Повторяемость ≠ правильность.** Нулевые метрики подтверждают идентичность трёх запусков, но не доказывают биологическую корректность обработки.
